## 已具備的邊界

- `main.js` 防止重複啟動，`app.js` 集中組裝模組與處理帳號、畫面、停用狀態。
- `core/model.js` 負責資料結構、驗證及舊動畫總時長轉換；`store.js` 先驗證副本，再壓縮保存。同步呼叫丟錯時還原本地 ExtensionSettings，沒有宣稱遠端寫入已獲確認。
- `core/engine.js` 將事件匹配、回應抽選、去重及計時器取消與遊戲 API 分開；執行前重查事件有效性。
- `integrations/events.js` 集中遊戲 hooks；離房事件保留房名快取，且不要求 ChatRoomData 在離房時仍存在。`ServerSend(ChatRoomLeave)` 之前同步提交回應。
- `features/output.js` 統一 BCX 檢查、文字、互動、表情及動畫輸出；多部位動畫共享切換間隔並支援取消還原。
- `activity-picker.js` 以請求序號排除過期非同步結果，會話重設清除快取。
- UI 的 `editingPersonaId` 與實際使用的 `activePersona` 分離；退出重設介面狀態，衣櫃往返例外保留編輯工作。
- 翻譯測試檢查鍵、插值參數與未翻譯英文占位文字；產品名稱和同形詞有明確例外。

## 維護風險與建議

| 優先度 | 觀察                                                                           | 影響與建議                                                                                                                                 |
| ------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 中     | `ui/dom-settings.js` 集中人格、規則、對話框、衣櫃狀態及事件綁定                | 後續新增大型功能時，優先抽離人格編輯狀態與對話框渲染／控制。不要僅為縮短檔案而拆成仍共享大量閉包狀態的小檔。                               |
| 中     | `namespace.stop()` 清理工作、訂閱與監控，但保留 SDK hooks 和註冊的訊息 handler | 現在是「停止功能」，不是完整卸載，也不支援同頁重新 start。若要提供熱重載，需統一 dispose 契約，追蹤每個 hook、handler、UI 註冊的清理方式。 |
| 中     | 初始化中途失敗僅 reset 並回報；先前已安裝的 hooks 不會回滾                     | 若某個遊戲 API 或第三方環境在安裝中途丟錯，可能留在部分初始化狀態。未遇到此故障；若新增初始化重試，必須先加入安裝回滾，避免重複掛接。      |
| 中     | `store.load()` 的讀取／遷移路徑與 `update()` 的保存路徑不同                    | `update()` 有同步呼叫失敗回滾與 60 KB 限制，舊資料遷移直接寫入。未來應抽出共用保存函式，使遷移也有同樣的邊界。                             |
| 低     | `app.js` 每次資料更新都取消排程、嘴型與動畫                                    | 安全但較粗粒度，編輯未啟用人格也會中斷當前動畫。可在有需求時依設定差異做精準取消；本次不改動已驗證的行为。                                 |
| 中     | 設定頁測試主要依靠 DOM stub，真實 ESC、對話框、衣櫃來回仍有覆蓋缺口            | 應逐步加入真實 DOM 操作回歸，尤其未保存退出、編輯非主人格、刪除非選取規則。既有使用者實測有效，不代表所有退出路徑都已自動化驗證。          |

## 執行流程

一般回應：BC hook → 標準事件 → app 有效性檢查 → engine 匹配／抽選／排程 → 再次檢查 → output → BC API。

離房文字：離房上下文／快取 → 攔截離房封包 → 同步執行文字回應 → 原離房封包；略過規則延遲與主回應間的 50 ms 等待，不使用已被刪除的 InputChat。

動畫：讀取 A/B 狀態 → 每隔 intervalMs 更新所有部位 → 完成回到 A；中途取消還原開始前的外觀。舊 durationMs 在資料驗證時除以次數轉為 intervalMs。

編輯保存：選取編輯人格 → 編輯草稿 → store.update 副本 → validateData → 壓縮 → BC 同步 → 發佈資料更新。
